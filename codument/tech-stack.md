## 架构决策

### ADR-001: 使用 Bun 作为运行时

**状态**：已采纳

**背景**：
需要选择 JavaScript/TypeScript 运行时环境，用于构建 CLI 工具。

**决策**：
选择 Bun 作为运行时，因为：
- 内置 TypeScript 支持，无需额外编译配置
- 支持 `--compile` 生成单文件可执行文件
- bunfs 机制自动嵌入静态资源（提示词文件）
- 更快的启动和执行速度

**后果**：
- 正面：开发体验更好，构建产物简洁
- 负面：生态系统相对较新，某些 Node.js 库可能不兼容

### ADR-002: 使用文件系统存储状态

**状态**：已采纳

**背景**：
需要持久化项目状态和配置。

**决策**：
使用文件系统存储，包括：
- JSON 文件存储元数据和状态
- XML 文件存储任务结构
- Markdown 文件存储文档和规范

**后果**：
- 正面：无外部依赖，易于版本控制，人类可读
- 负面：无法支持并发访问，大数据量性能受限

### ADR-003: 提示词嵌入可执行文件

**状态**：已采纳

**背景**：
需要将提示词文件随 CLI 一起分发。

**决策**：
使用 Bun 的 bunfs 机制：
- 使用 `__dirname` + `fs.readFileSync` 加载提示词
- Bun 构建时自动嵌入到 bunfs 虚拟文件系统

**后果**：
- 正面：单文件分发，无需额外资源文件
- 负面：提示词更新需要重新构建

## 技术约束

1. **版本兼容性**：所有依赖必须支持 Bun 运行时
2. **安全更新**：依赖必须定期更新以修复安全漏洞
3. **许可证**：只使用 MIT 或类似开源许可证的依赖
4. **构建产物**：必须能生成单文件可执行文件
