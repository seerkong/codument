# Upgrade Track

`codument upgrade-track` upgrades a single track (active or archived) to the latest plan.xml conventions that support wave execution.

This is useful when you have an existing track written in the older format (for example it contains `<dependencies>` tags or uses task body mixed text) and you want to migrate it so you can use the wave-based workflow (`/codument:plan-wave`, `/codument:execute-wave`) and the newer schema.

## What It Does

Given a target track directory (either `codument/tracks/<track-id>/` or `codument/archive/<archive-id>/`), it upgrades:

- `plan.xml`
  - Removes `<dependencies>...</dependencies>`
  - Ensures `<execution_mode>` exists under `<metadata>` (defaults to `wave`)
  - Wraps task description text into `<description>...</description>` (preferred format)
  - In `wave` mode, auto-generates a `<waves>` DAG for each phase and adds `wave="..."` on each task
  - Best-effort converts legacy `<references>/<reference>` into `<context_files>/<file>`

In `wave` mode it also ensures these files/directories exist in the track directory:

- `context.md`
- `state.md`
- `phases/`
- `waves/`

It does NOT change:

- Any other tracks
- `codument/specs/`

## Backup And Rollback

By default it creates a full backup of the target track directory under:

`./.tmp/codument/upgrade-track-<timestamp>/...`

The backup mirrors the original relative path, so rollback is just copying files back.

## Usage

Upgrade an active track:

```bash
codument upgrade-track add-user-auth
```

Upgrade an archived track (provide the archive id or the track id):

```bash
codument upgrade-track 2026-01-11-create-codument-prompts-20260101
codument upgrade-track create-codument-prompts-20260101
```

Options:

- `--mode wave|sequential`
  - `wave` (default): generate waves + set execution_mode to wave
  - `sequential`: only modernize schema (remove dependencies, add description) without waves
- `--backup-dir <path>`: use a custom backup directory
- `--no-backup`: skip backups (not recommended)

## Notes

- The wave DAG generated by this command is conservative: it assigns one wave per task in the order tasks appear, and translates `<dependencies>` (task ids) into `depends_on` relations between waves within the same phase.
- After upgrading, you can refine the wave plan using `/codument:plan-wave`.
